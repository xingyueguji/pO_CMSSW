# pO-derived Z→ee electron pT scale & smearing (2025)

Source of truth: `pO_electron_corrections_raw.h` in this directory
(autogenerated from the pO 2025 Z→ee calibration, 23 nb⁻¹, basis = raw
GSF `eleRawPt`, region selector = `eleSCEta`).

The two `.dat` files are a conversion of the header's constants into the
5-line format read by `EnergyScaleCorrector`
(`EGMAnalysis/src/EnergyScaleCorrector.cc`), so the corrections can be
applied *in-forest* by the `correctedElectrons` producer:

```
line 1: hiBin upper edges          -> "200" = single bin, all centralities
line 2: EB scale per bin
line 3: EE scale per bin
line 4: EB smear per bin (GeV)
line 5: EE smear per bin (GeV)
```

| file | used by | scale EB / EE | smear EB / EE |
|---|---|---|---|
| `SSpORun2025.dat` | DATA configs | 1.020817 / 1.087120 | 0 / 0 |
| `SSpO2025MC.dat`  | MC configs   | 0.996921 / 0.993451 | 0.8950 / 4.8653 GeV |

Smear conversion: `EnergyScaleCorrector` draws `Gaus(1, smear/91.1876)`,
so `smear(.dat) = relative smear(.h) × 91.1876`:
`0.009815 × 91.1876 = 0.895006`, `0.053355 × 91.1876 = 4.865314`.

## Known differences vs the header (accepted, small)

- **EB/EE boundary**: `EnergyScaleCorrector` splits at `|scEta| < 1.5`;
  the header uses 1.4442. Electrons in 1.4442–1.5 (crack) get the EB
  numbers in-forest.
- **Application point**: in-forest the scale multiplies `ecalEnergy` and is
  then propagated through the E–p combination, so the resulting `elePt` is
  ≈ (not exactly) `scale × rawPt`. The header applies the scale directly to
  raw pT. For Z/W-like electrons (ECAL-dominated) the difference is
  negligible.
- **minPt**: the producer skips electrons below `minPt` (default 20 GeV),
  same as in the pO production.

The forest always stores the uncorrected pT as `eleRawPt` (and
`eleSCEta`), so the header can still be applied downstream on the trees —
that path remains the calibration's native basis.

These constants were derived on **pO 9.62 TeV** data. They are applied to
the **OO 5.36 TeV** forests as the best available 2025 detector-period
calibration until an OO-specific Z→ee derivation replaces them —
regenerate with the same workflow on OO data and update the two `.dat`
files (and the header) here.
